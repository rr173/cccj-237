# 离线仓储计费（billing）

财务给定一份带统一时间基准的仓内动作流水、一份 JSON 价目表和账期
`[start, end)`（整数分钟），本入口离线算出每个**仓 × 物料 × 原收料动作序号 ×
库位**在账期内的两档件分钟与整数微元费用。**只读流水、不改库存**，保留原有
全部命令，不做跨仓归集，也不开发票。

## 运行

```bash
python3 -I run_slicer.py billing \
    --flow   samples/billing_flow.json \
    --prices samples/billing_prices.json \
    --start  3 --end 12
```

- 成功：stdout 输出一份 JSON 账单（可加 `--out 账单.json` 同时落盘），退出码 `0`；
  账期内没有正常在库占用时 `details` 为空、总额为 0，也算成功。
- 失败：stderr 指出具体动作或库位与分钟时段，退出码 `1`，**不输出账单**。
- `--flow` 复用现有流水格式（`.json` 动作数组或旧系统 `.csv`），只是每条动作
  额外带一个非负整数 `minute`。

## 时间模型

- `minute` 是统一时间基准上的**非负整数分钟**；分钟 `t` 指半开区间 `[t, t+1)`。
- 同 (仓, 物料) 仍按原动作序号 `seq` 执行；`minute` 必须**非递减**（时间不得
  倒退）。同一分钟内的动作按序生效，**动作之间不计时间**。
- 重送动作的 `minute` 也必须相同（`minute` 计入幂等内容签名）；同身份但
  `minute` 不同按断点处理。
- 流水“含截至 `end` 的动作”：恰在 `end` 的动作照常参与流水校验，但**不收费**；
  `minute > end` 属于非法时间。
- 分钟 `t` 的状态是该分钟起点动作全部生效后的状态。账期只对
  `start <= t < end` 的分钟收费。

## 在库时长怎么累计

每段货（按原收料的原料段区分）从**收料**起，只累计**正常在库**时间：

| 动作 | 对累计时长的影响 |
|---|---|
| receive 收料 | 从收料分钟起算，初始累计 0 |
| isolate 隔离 | 暂停累计（隔离期不算正常在库） |
| issue 领料 | 暂停累计（被领料占用期不算） |
| release 放行 | 回正常库存，**接着**累计（不清零） |
| return 退料 | 回正常库存，**接着**累计（不清零） |
| transfer 移位 | 费用归新库位，累计时长**不清零**；移位分钟即归新库位 |

部分动作（隔离/放行/移位/领料/退料只裁一部分）只影响所涉原料段，不改变已有
FIFO，也不重扫无关库存。期前（`t < start`）的流水照常重放，用来算期初状态与
每段已累计的正常在库分钟，但期前时间**不收费**。

## 价目表

```json
{
  "threshold_minutes": 5,
  "rates": [
    {"warehouse": "WH1", "location": "A", "effective_minute": 0,
     "price_tier1": 10, "price_tier2": 18},
    {"warehouse": "WH1", "location": "A", "effective_minute": 8,
     "price_tier1": 12, "price_tier2": 20},
    {"warehouse": "WH1", "location": "B", "effective_minute": 0,
     "price_tier1": 7, "price_tier2": 15}
  ]
}
```

- `threshold_minutes`：统一的**正整数**门槛（分钟）。每分钟按该分钟**开始时**
  该原料段已累计的正常在库时长选档，`累计 >= threshold` 即用第二档，否则第一档。
- `rates`：按 (仓, 库位) 给出的费率；`effective_minute` 是非负整数生效分钟，
  同一 (仓, 库位) 内生效分钟不得重复；两档单价 `price_tier1/2` 都是非负整数
  （微元/件/分钟），**零价有效**。
- 每分钟取当时**最新生效**（`effective_minute <= 该分钟` 的最后一条）的费率。
- 即使没有仓库动作，库存也可能随时间**跨档**（累计到门槛）或遇到**改价**；
  这两类边界都按分钟区间处理，不依赖动作分钟。
- 只有本期内有正时长的正常在库才需要费率；应收费的分钟找不到有效费率即失败，
  错误会定位到仓、库位与分钟时段。

## 输出

```json
{
  "period": {"start": 3, "end": 12},
  "threshold_minutes": 5,
  "details": [
    {"warehouse": "WH1", "material": "M1", "receipt_seq": 1, "location": "A",
     "piece_minutes": {"tier1": 19, "tier2": 27},
     "fee_micro": {"tier1": 194, "tier2": 522},
     "fee_total_micro": 716}
  ],
  "total_fee_micro": 1156
}
```

- `details` 按 (仓, 物料, 原收料动作序号, 库位) 排序；每组给两档**件分钟**
  （件数 × 分钟）、两档整数微元费用与该组费用合计。
- `total_fee_micro` 是全部组费用合计；无占用时为空明细、零费用。
- 全程只处理整数区段与区间对象，**不逐件、不逐分钟展开**；一次动作只更新它
  实际触及的原料段。

## 手算核对（samples/billing_flow.json，账期 [3,12)）

一批 10 件在分钟 0 收于库位 A，门槛 5 分钟。库位 A 在分钟 8 改价
（10/18 → 12/20），库位 B 全程 7/15。

| 分钟 | 事件 | 正常在库分布（件 → 库位） |
|---|---|---|
| 0 | 收料 10 件 →A | 10 → A |
| 2 | 隔离 [0,4) 共 4 件 | 6 → A（4 件暂停） |
| 4 | 移位 [4,7) 共 3 件 A→B | 3 → A、3 → B、4 暂停 |
| 6 | 放行 4 件回 A | 7 → A、3 → B |
| 8 | 领料 [0,2) 共 2 件；同分钟退这 2 件 →B | 4 → A、6 → B |
| 12 | 领料 3 件（恰在 end，验证不收费） | — |

逐件按“分钟开始时累计时长”选档（隔离/领料期暂停，放行/退料接续，移位不清零），
账期 t=3..11 汇总：

| 库位 | 一档件分钟 | 二档件分钟 | 一档费用 | 二档费用 | 合计 |
|---|---:|---:|---:|---:|---:|
| A | 19 | 27 | 194 | 522 | 716 |
| B | 5 | 27 | 35 | 405 | 440 |
| **合计** |  |  |  |  | **1156** |

覆盖的核对要点：同一收料一部分隔离后放行返回（[0,4)）、另一部分移位
（[4,7)）；账期从分钟 3 中途开始；分钟 5 跨门槛（一档→二档）；分钟 8 库位 A
改价；分钟 8 同分钟领料+退料（进出之间零时长）。引擎结果与一个独立的逐件
逐分钟形式化参考实现（见 `tests/test_billing.py` 与随机差分测试）逐项一致。

## 失败模式（退出码 1，不交部分账单）

- 仓内流水断点（数量不足、非法引用、序号冲突、同身份内容不同等，复用原引擎报告）；
- 时间非法：动作缺 `minute`、`minute` 为负或回退、`minute > end`；
- 价目表非法：门槛非正整数、生效分钟重复、单价为负、字段缺失或多余、类型不符；
- 账期非法：不满足 `0 <= start < end`；
- 应收费的正常在库分钟在对应 (仓, 库位) 找不到有效费率（定位库位与分钟时段）。
