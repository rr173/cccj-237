# 手算核对（samples/flow_main.json）

记号：`R1[起,末)` 表示收料 seq=1 的原料段，数量 = 末 − 起。
- R1 = B-OLD，货龄起点 2026-01-10，100 件，即 R1[0,100)
- R2 = B-NEW，货龄起点 2026-02-15，80 件，即 R2[0,80)

正常库存选取键：`(货龄起点, 收料序号, 段起点)`，所以任何动作都先吃 R1 再吃 R2，
部分裁取从切片**区段起点**开始。

## 三个必须人工确认的点

1. **库位变更不改变货龄**：seq 9 的 D3 先取 L2 的 R1[40,60)（货龄 2026-01-10），
   而不是 A/L1 上的 B-NEW——该 R1 切片经历过隔离、放行、换库位，年龄起点仍是收料日。
2. **合计相同 ≠ 同批次**：测试 `TestSameTotalDifferentBatches` 中，两笔都是领 10，
   老批次库存 10 时全部取自 OLD；老批次只有 4 时拆成 OLD×4 + NEW×6。
   看总量无法区分，必须看交付表的批次切片行。
3. **原料段可核验、不复制数量**：期末把 R1 的全部存活子片按段起点排序，
   恰为 [0,27) [27,40) [40,60) [60,80) [80,100)，无缝无重叠并满 [0,100)；
   R2 同理满 [0,80)。引擎的 `reconciliation.coverage_ok` 即此项自动校验。

## 小数量独立手算（TestSmallHandCalculation）

收 X×5（1/1 到货）、Y×5（2/1 到货）：隔离 3 → 领 4 → 放行 2 → 退 3。

- 隔离 3：X[0,3) 进笼，正常剩 X[3,5)、Y[0,5)
- 领 4：取 X[3,5)（2）+ Y[0,2)（2）
- 放行 2：只在隔离动作尚持有的 X[0,3) 内取 X[0,2) 回 A，笼里剩 X[2,3)
- 退 3：从最后取走的 Y[0,2) 全退（2），再从 X[3,5) 末端退 X[4,5)（1）到 B
- 期末 D1 仍占用 X[3,4)（1 件）；总量仍为 10，守恒通过
